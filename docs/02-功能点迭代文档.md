## 3. V0.1 —— MVP 核心闭环

**版本目标**：跑通「上传 → 3×3 方块拼图 → 拖拽交换 → 完成庆祝」最小可玩闭环，部署上 GitHub Pages。

### F-001 上传本地图片 · P0

- **描述**：用户通过文件选择器或拖放上传一张本地图片作为拼图素材。
- **交互细节**：首页大按钮「上传图片」；支持将图片文件直接拖入页面；上传后显示预览并进入难度确认（V0.1 固定 3×3）。
- **边界条件**：仅接受 png / jpg / webp；非图片文件给出 toast 提示；超大图（> 4096px 边长）自动等比缩放；EXIF 方向自动修正；解码失败给出友好报错。
- **验收标准**：上传后 1s 内完成预览；**图片数据不发起任何网络请求**（DevTools Network 面板验证）。
- **自动化**：ImageProcessor 缩放/方向修正单测。

### F-002 内置示例图 · P0

- **描述**：提供 3–5 张内置示例图（`public/samples/`），无本地图片也可开玩。
- **验收标准**：点击示例图直接进入拼图；示例图随应用静态资源一并部署。

### F-003 3×3 切图与打乱 · P0

- **描述**：将图片按 3×3 等分为 9 块并随机打乱。
- **交互细节**：图片按舞台比例**居中裁剪（cover）**保证棋盘满铺无黑边；打乱动画（块飞入随机格）。
- **边界条件**：打乱结果不得为完成态；9 块时额外保证无一块位于原位。
- **验收标准**：任意长宽比图片均能切出 9 块有效图像；连续开局 20 次无一次直接完成态。
- **自动化**：Slicer 切块正确性、Shuffle 状态校验单测。

### F-004 拖拽交换 · P0

- **描述**：按住任意未锁定块拖动，松手落到目标格。
- **交互细节**：拖拽中块置顶（z-index 提升）并带轻微放大阴影；落在已占用格 → 与该块**互换**；落在锁定块上 → 无效，弹回原格；支持鼠标与触屏。
- **边界条件**：拖出棋盘边界释放 → 弹回；多点触控同一时刻仅响应一只指针。
- **验收标准**：桌面与移动端拖拽流畅（目标 60fps）；拖拽时页面不发生滚动。

### F-005 吸附 · P0

- **描述**：释放时自动吸附到最近的格子中心。
- **交互细节**：吸附阈值 = 0.35 × min(格宽, 格高)；吸附动画约 120–150ms 缓动；落在正确格（cellIndex === id）的块**锁定置底**并播放正确提示音（V0.1 可先只有动画）。
- **验收标准**：松手位置任意，块最终均对齐格中心；锁定块不可再拖动。
- **自动化**：SnapSolver 吸附/交换/锁定判定单测。

### F-006 完成判定与庆祝 · P0

- **描述**：全部块归位后判定胜利，展示结算弹层。
- **交互细节**：胜利时全图短暂高亮 + 撒花动画；结算弹层显示「完成！」（V0.2 起追加用时/步数）与「再玩一次」「换一张图」。
- **验收标准**：9 块全对后 300ms 内弹出结算；再玩一次重新打乱同一图，换图返回首页。

### F-007 重新开始 · P1

- **描述**：对局中提供「重新开始」按钮，重新打乱当前图片。

**V0.1 验收口径**：从上传到完成一局全程无卡顿、无报错；GitHub Pages 线上地址可访问、可完整玩一局。

## 4. V0.2 —— 难度与配置

**版本目标**：拼图数量可配置，核心反馈（计时/步数/参考图）齐备。

### F-101 预设难度档位 · P0

- **描述**：提供档位：`3×3(9) 入门 / 4×4(16) 简单 / 5×5(25) 中等 / 6×6(36) 困难 / 8×8(64) 大师 / 10×10(100) 地狱`。
- **交互细节**：难度选择卡片，每档显示块数与预估难度；选中档位记忆到本地（下次默认）。
- **验收标准**：各档位切图、打乱、完成判定均正常；100 块档可正常游玩。

### F-102 自定义行列 · P0

- **描述**：行数、列数独立可选（各 2–10），块数 = 行 × 列。
- **交互细节**：选择器旁实时显示「N 块」；带网格线预览缩略图，所见即所得。
- **边界条件**：2×10 / 10×2 等极端长条布局需可玩（块为长条形）。
- **验收标准**：任意 2–10 × 2–10 组合可开局并完成。

### F-103 计时 · P0

- **描述**：对局用时 mm:ss 显示。
- **边界条件**：页面切后台（`visibilitychange`）自动暂停计时，回前台继续；结算取净用时。
- **验收标准**：计时与真实操作时长偏差 ≤ 1s。

### F-104 步数统计 · P0

- **描述**：有效交换次数计数（弹回不计）。
- **验收标准**：每次交换 +1，弹回与无效落点不计。

### F-105 原图参考 · P1

- **描述**：提供原图半透明底图开关（默认关），或悬浮小缩略图。
- **交互细节**：底图透明度默认 20%，可调；开启底图不影响判定。
- **验收标准**：开关即时生效且状态持久化。

### F-106 锁定开关 · P1

- **描述**：设置中可关闭「正确即锁定」（关闭后正确块仍可拖动，便于追求步数极限的玩家）。

### F-107 重新打乱 · P1

- **描述**：同图同难度一键重新打乱，计时步数清零。

## 5. V0.3 —— 体验与持久化

**版本目标**：移动端一等公民体验；进度与成就不丢失；可安装。

### F-201 移动端适配 · P0

- **描述**：手机/平板完整可玩。
- **交互细节**：响应式布局（竖屏棋盘占满宽度）；触控目标 ≥ 44px；禁用双击缩放与长按菜单；拖拽命中半径外扩 8px（小尺寸块）。
- **验收标准**：iPhone SE（375px 宽）与 iPad 上完整通过 V0.1 全部验收项。

### F-202 动画打磨 · P1

- **描述**：开局块飞入动画、吸附弹性动画、胜利撒花粒子上量与节奏优化；遵循 `prefers-reduced-motion` 降级。

### F-203 音效 · P1

- **描述**：拾起 / 落格 / 吸附正确 / 胜利四种音效（Web Audio 合成或短采样）。
- **边界条件**：浏览器自动播放策略——首次用户手势后才初始化音频上下文；静音开关持久化。

### F-204 最佳记录 · P1

- **描述**：按行列分档记录历史最佳（最短用时 + 最少步数），结算弹层展示「新纪录！」。
- **验收标准**：记录存 localStorage，清缓存后消失；各难度互不干扰。

### F-205 进度恢复 · P0

- **描述**：对局中刷新/关闭页面，下次打开可「继续上局」。
- **交互细节**：每次落位节流写入快照（布局 + 步数 + 用时 + 图片引用）；图片本体存 IndexedDB（最近 5 张）。
- **边界条件**：图片缓存被清除时快照作废并提示重新选图；首页提供「继续上局」入口与「放弃」。
- **验收标准**：任意时刻刷新后 2s 内恢复到刷新前局面。

### F-206 PWA · P2

- **描述**：manifest + Service Worker（vite-plugin-pwa），可安装到主屏；示例图离线可玩。
- **边界条件**：SW 作用域为 `/TinyPuzzle/`；版本更新提示「新版本可用，点击刷新」。

## 6. V0.4 —— 进阶玩法

**版本目标**：从「方块交换」扩展到「拟真拼图」，丰富玩法层次。

### F-301 异形拼图块 · P0

- **描述**：经典凹凸边拼图形状，相邻块边线凹凸互补。
- **交互细节**：难度面板新增「形状：方块 / 经典」选项（仅 V0.4 起可用）；块渲染改为独立离屏 canvas 切片。
- **边界条件**：边缘块靠外侧两边为平边；凹凸方向随机翻转避免规律感。
- **验收标准**：相邻块拼合视觉无缝；命中测试按不规则形状判定（点击凸起外的空白不选中块）。
- **自动化**：路径生成器单测（相邻边互补性断言）。

### F-302 自由摆放模式 · P0

- **描述**：新玩法：块散落托盘区（棋盘四周），仅可吸附到**正确**格，不存在交换。
- **交互细节**：与交换式在开局时选择；托盘块可任意堆叠，拖入正确格附近自动吸附锁定。
- **验收标准**：两种模式共用难度/计时/记录体系；free 模式完成判定正确。

### F-303 旋转模式 · P2

- **描述**：可选项：块初始随机旋转 0/90/180/270°，需双击（或长按）旋转正确后才可吸附。
- **边界条件**：仅 5×5 以上难度开放选项；异形块旋转后命中测试同步旋转。

### F-304 提示功能 · P1

- **描述**：每局限 3 次「提示」：高亮一块及其正确格位置 2 秒。
- **边界条件**：free 模式下高亮「块 → 目标格」；swap 模式下高亮「块 → 应交换到的格」。
- **V1.5 增强**：寻块指引与持续高亮由 F-514 / F-515 承接，细节修缮见 F-516。

### F-305 结算分享图 · P2

- **描述**：结算页可生成分享图（完成图缩略 + 用时/步数/难度角标）并下载 PNG。
- **验收标准**：生成在本地 canvas 完成，无网络请求；文件名含难度与日期。

## 7.5 V1.1 —— 玩法与体验升级

**版本目标**：从「小棋盘选玩法」收敛为「大块数拟真拼图」：难度按目标块数配置、行列随图片比例自适应；视口可缩放平移以驾驭大棋盘；渲染高清化；并补齐 CI 质量门禁。

### F-501 比例自适应切割 · P0

- **描述**：难度改为按**目标块数**配置（预设 500 / 1000 / 2000，自定义 100–4000），行列由 `fitGrid` 按图片真实宽高比计算（`rows = round(√(target/ratio))`，`cols = round(rows×ratio)`），格子保持接近正方形，**图片不再居中裁剪**；单边范围 2–220。
- **验收标准**：任意宽高比图片切割后无内容丢失（不裁剪）、格子无极端长条；实际块数显示在难度卡片上。
- **自动化**：`fitGrid` 边界（极端比例、触顶反向重算、夹取）单测。

### F-502 玩法收敛固定 · P0

- **描述**：移除形状 / 玩法 / 进阶选项，固定为「经典凹凸 + 自由摆放 + 可旋转」；设置面板仅保留难度与辅助项（锁定开关、原图参考、音效、语言、编码开关）。
- **边界条件**：引擎保留 `swap` / `square` 抽象与单测，仅界面不再暴露。

### F-503 视口缩放与平移 · P0

- **描述**：拼图区域支持滚轮缩放（以指针为中心）与双指捏合缩放，范围 0.5×–6×；空白处拖拽平移；平移范围自动夹取，棋盘不会被拖丢。
- **验收标准**：2000 块档下可缩放到单格级别操作；散落场（棋盘 2 倍见方，四周各外扩 50%）配合缩放可查看视口外的散块。

### F-504 高清渲染与真实卡口 · P1

- **描述**：舞台位图最长边提升至 2048px（原图不裁剪），拼图块以 2~3 倍超采样渲染；卡口造型重做为真实拼图蘑菇头（8 段贝塞尔：颈部收窄 + 头部外翻 undercut + 圆拱收边）。
- **验收标准**：6× 缩放下块边缘无明显锯齿；相邻块拼合视觉无缝；舞台导出优先 WebP 控制体积。

### F-505 旋转交互调整 · P1

- **描述**：键盘 Q / E 左右旋转（拖拽中可用，R 等效顺时针）；触屏长按旋转；**移除双击旋转**。
- **验收标准**：拖拽中旋转即时生效且松手姿态不跳变、不抖动。

### F-506 网格 A1 编码与翻面查看 · P2

- **描述**：设置新增「网格编码」开关（默认关）：开启后网格层显示 A1 式编码（列字母 + 行号，26 列起 AA…），拼图块可双击翻面查看背面印刷的正确格编码。
- **验收标准**：开关即时生效并持久化；翻面为纯视觉变换，不影响判定与进度快照。

### F-507 自由摆放体验修正 · P1

- **描述**：散落块可吸附停在**任意空格**（不判正确性、永不锁定，可再次拖动）；修复自由摆放初始化竞态、点击格上块误散置、示例图误触发上传等缺陷。
- **验收标准**：格上块点击不散置；开局散布无竞态；示例图区域点击不弹出文件选择。

### F-508 CI 流水线 · P1

- **描述**：新增 `.github/workflows/ci.yml`：push 到 `main` 与全部 PR 触发 `typecheck + test + build`，产物留档 7 天（部署仍走 `deploy.yml`）。
- **验收标准**：CI 在 PR 上红线/绿线可用，失败阻断合并判断。

### F-509 示例图与视觉细节 · P2

- **描述**：内置示例图更换为四张实景 JPG；首页上传区改为虚线拖放区（点击/拖入仅限该区域，不再误触发）；语言按钮与滚动条样式优化。
- **验收标准**：示例图加载与离线可玩正常；上传区外点击不打开文件选择器。

## 7.6 V1.2 —— 质感与物理

### F-510 液态玻璃质感 · P1

- **描述**：拼图块呈现磨砂玻璃质感 —— 切片生成期在 canvas 内叠加模糊底图折射层（放大 1.06 + `screen` 混合）、对角高光扫掠、内侧柔光与对角菲涅尔亮边描边，玻璃强度随格子尺寸自适应；棋盘托盘与工具栏按钮 `backdrop-filter` 轻度玻璃化（不支持时回退实底色），拿起块提亮增饱和，翻面卡背磨砂化。

## 7.8 V1.4 —— 性能专项

### F-513 性能审计与热点优化 · P1

- **描述**：针对大块数（476 / 960 / 2030）与低端移动端做一轮性能审计，共落地九项修复：

  4. **物理运动 transform 化**：`physLoop` 运动期以「锚点 + translate3d」写合成器属性（不再每帧写 `left/top` 触发布局），静置 / 被拾起 / 重开 / 关闭物理时一次性落回 `left/top`；

  7. **舞台图 Blob URL 化**：`StageImage.dataUrl(base64) → url(Blob)`，免 base64 +33% 字符串驻留，换局时回收旧 URL；`toBlob` 不可用时回落 JPEG dataURL；

  9. **物理 broadphase**：空间哈希 / 子步进 / dynamic 上限维持 V1.2 设计（审计确认无瓶颈）。
- **回归修复（V1.4 收尾）**：图集化曾引入两处视觉回归——① 双击翻面显示镜像图而非背面卡（正面背景挂在元素自身，元素背景无背面概念，翻转后镜像透出）：正面下沉为 `.piece-front` 子层并 `backface-visibility: hidden`，背面卡恢复；② 锁定绿色轮廓辉光消失（渲染管线先滤镜后裁剪，元素自身 clip-path 把轮廓外的 drop-shadow 一并裁掉）：裁形移至子级、滤镜留在 `.piece` 父级渲染于裁剪之外，辉光恢复，提示脉冲辉光一并恢复。
- **验收标准**：476 / 960 块位图内存降至两位数 MB；落子 / 旋转 / 提示无 O(n²) 尖峰；拖拽 / 物理惯性 / 吸附 / 旋转 / 翻面 / 命中测试行为与 V1.3 一致（异形块视觉含玻璃质感）；`tsc` 与全部测试通过。

## 7.9 V1.5 —— 提示体验专项

> 背景：实测提示链路存在两处断点——块可能散布在棋盘四周场地、被物理滑到任意角落或缩放平移后处于视口外，「找不到被提示的碎块」；且目标格高亮 2 秒即消失，「来不及处理」。本版本聚焦提示链路的「看得到、来得及」，实现不动次数规则。

### F-514 提示寻块指引 · P1

- **描述**：被提示块不在视口内时，在视口边缘显示指向它的橙色箭头，保证「提示了就找得到方向」；**不移动用户视口**（不做镜头巡览 / 自动平移）。
- **交互细节**：块中心在视口外（含被视口边缘裁切）时，箭头贴视口边缘、指向块的实际方向，直至提示解除；块回到视口内后箭头消失，仅保留块与目标格的持续高亮（F-515）。箭头位置低频更新（平移 / 缩放 / resize / 物理滑行事件驱动 + 1s 兜底），不做每帧循环；不改变缩放倍率与平移位置。
- **边界条件**：提示触发守卫沿用现状（动画中 / 拖拽中不可用）；物理模式下块滑行时箭头低频跟随（近似方向），由 F-515 持续高亮兜底；目标格被其他块占用时照常指引（先移开占块）。
- **验收标准**：视口外的提示块始终有边缘箭头指引方向，回到视口内箭头即消失；无每帧循环；箭头不遮挡棋盘交互（`pointer-events: none`）。

### F-515 提示持续与解除策略 · P1

- **描述**：提示从「2 秒定时消失」改为「持续生效、条件解除」，解决来不及处理的问题。
- **交互细节**：前 2 秒强化脉冲（块辉光呼吸 + 目标格虚线呼吸），之后转为常亮高亮直至解除。解除条件（任一）：① 被提示块**放置到正确位置**（归位 / 锁定，swap 模式即交换落定）——拾起仅暂隐块辉光 / 角标 / 边缘箭头，目标格转常亮保持（拾起不丢目标格指引，放置结算时归位即整体解除、未归位即恢复块辉光与角标）；② 再次使用提示——旧提示立即解除，全场同时最多一个活动提示；③ 重开 / 解出 / 离开局面。次数规则不变（每局 3 次、无可提示块不消耗）。
- **边界条件**：目标格被占用时保持高亮；拾起后原地无操作（自由模式点击不拖动）同样视为一次放置结算（归位即解除 / 未归位即恢复）；解除逻辑统一走清理函数，杜绝残留定时器 / 样式类（复用 `later()` 与 destroy 清理）。
- **验收标准**：拾起被提示块后目标格虚线框保持可见，放置到正确位置才消失；放错位置（含原地无操作 / 物理滑行落点）提示立即恢复；提示保持到用户完成操作或触发解除；无残留高亮 / 定时器；重开后计数与高亮正确复位。

### F-516 提示细节修缮 · P2

- **描述**：三项体验修缮打包：
  1. **图层顺序修复**：`.cell-hint`（z-index 25）提到原图参考层（26）之上——参考底图开启时目标格虚线框不再被罩暗（实际缺陷）；
  2. **旋转角标**：被提示块 `rot ≠ 0` 时叠加 🔄 角标，明确「这块需要双击旋转」（位置正确仅旋转错误时尤其必要）；
  3. **智能选块**：候选优先级——「仅旋转错误（双击即完成）」与「目标格空闲」优先，同级随机，避免提示一个暂时动不了的块。
- **验收标准**：参考图与提示同开时虚线框清晰；rot ≠ 0 的提示块有旋转标识；仅旋转错误与目标格空闲的块优先被选中。

### F-517 拖拽热路径性能修复 · P1

- **描述**：修复「缩小视口后拖动卡顿」。实测 510 块穿板拖拽每步 pointermove 处理耗时 3.07ms（缩放 1.0）/ 5.22ms（缩放 0.5，P95 8.8ms、145/145 步 >1ms），根因是跨格悬停链路「写落点框百分比几何 → 读 offsetWidth 强制重排全棋盘子树」在每个指针事件上循环一次；缩小后屏幕格尺寸减半、跨格频率 ≈×1.7 使其显性化，重排成本随块数线性（2040 块约 ×4）。量化定位用同步事件计时 + 落点框 MutationObserver 翻动计数。
- **交互细节**：三项修复——① `localSize()` 热路径（跨格悬停 / 拖拽 / 物理循环 / 命中测试）改读视图层尺寸缓存，仅 fitBoard（含 resize）/ mount 后失效重读（平移缩放为 transform，不影响该值）；② 落点提示框（#drop-hint / #hint-cell）改 `transform` 定位、几何仅在格尺寸变化时写，单次跨格从 4 次几何写降为 1 次 transform 写且不再脏化布局；③ `pickAt` 命中测试改由引擎状态推算包围盒粗筛（格上块=元素盒含留白，散置块=freePos 盒随物理逐帧同步），全场仅读一次棋盘 rect，异形路径精测只对粗筛候选执行。
- **验收标准**：510 块穿板拖拽单步处理 < 0.3ms（实测缩放 1.0 / 0.5 分别 0.074 / 0.105ms，较修复前 ↓98%，>1ms 步数 145→0~2）；拾起无首击顿挫（原 ~20ms）；行为回归：吸附 / 交换 / 旋转 / 翻面 / 物理拾起与修复前一致；`tsc` 与全部测试通过。

### F-518 缩放拖拽渲染管线优化（整板提层） · P1

- **描述**：修复 F-517 之后的残留卡顿「缩放 0.5 拖拽仍不流畅」。帧级实测（510 块，rAF 帧间隔采样）显示 JS 同步路径已达 55µs/步却仍卡：缩放 1.0 拖拽 p50=16.7ms（满 60fps、0 帧超标），缩放 0.5 拖拽 p50=57.9ms（≈17fps、59/60 帧超 33ms）；**关掉物理（p50 47.5ms）与关掉磨砂 backdrop-filter（47.1ms）均无效**，Long Animation Frame 显示慢帧 script≈0、style/layout≈0——帧时间消耗在浏览器 raster/合成阶段，与两个此前的主要嫌疑（物理推挤重绘、玻璃模糊逐帧重光栅）均无关。根因定位：`#board` 以 `transform: scale(<1)` 缩放但非常驻合成层，被拖块（`will-change: transform` 独立合成层）在其上逐帧移动时，分数光栅 scale（0.5×1.04×DPR）无法稳定缓存，触发大面积重光栅；缩放 1.0 同一代码路径无此问题。
- **交互细节**：两项提层，视觉零变化——① `#board:has(.piece.dragging / .piece.held)` **拖拽期整板提层**：拖拽开始才把整板预光栅为常驻纹理（约 1412×794×DPR×4B，松手即释放），拖拽 / 跨格提示期间全部为纯合成器变换；不采用常驻 `will-change`（分数缩放下存在光栅 scale 失稳的已知病理，且平添空载显存），代价为拾起瞬间一次性整板光栅（≤1 帧量级）；② `#drop-hint` / `#hint-cell` 加 `will-change: transform`，跨格逐帧 transform 写归入合成路径（缩放 0.5 下跨格频率 ≈×1.7）。曾评估拖拽期降级 `.dragging` 三连滤镜：其滤镜结果随图层内容缓存、transform 移动不重跑，去掉会牺牲 F-510 拿起透光感，实测无效（S4/E7），不采纳。
- **验收标准**：510 块缩放 0.5 穿板拖拽 rAF 帧间隔 p95 < 20ms（修复前 62.3ms）、无 >33ms 帧；缩放 1.0 满帧无回归；空闲态 `#board` 计算样式 will-change=auto、拖拽中=transform（提层仅存在于拖拽窗口）；拖拽 / 平移 / 双指缩放 / 磨砂视觉与修复前一致。**方法论备注：流畅度必须以帧级指标验收（rAF 间隔分布），同步事件计时（F-517 手段）测不到渲染管线成本，本例即其盲区；帧级测量需在真实浏览器（DevTools Performance / Paint Flashing）完成，应用内浏览器环境的测量会话中途出现与改动无关的统一帧地板（交替注入 A/B 验证），绝对数值不可采信。**

### F-519 视口平移渲染管线优化与夹取常量化 · P1

- **描述**：修复「缩小到最小时拖动画布有延迟感」。平移热路径每个 pointermove 写 `#board` transform，但 `will-change: transform` 只在拖块期存在（F-518），平移 / 双指缩放 / 滚轮手势期间 `#board` 非合成层——非合成层 transform 变化逐帧全量重绘整棵棋盘子树（数百块双边阴影 / 圆角 / 图像切片 + 60px 模糊投影），缩放 <1 叠加分数光栅失稳（同 F-518 病理：帧耗时全在 raster/合成、script/style≈0；拖块路径修了、平移路径漏了。缩小后棋盘四周留白大、空白拖拽成为高频常规手势，故在最小缩放下显性化）。同步发现夹取量测滞后一拍：`clampPan` 每事件 2 次 `getBoundingClientRect`（读到的是上一事件写入的 transform 渲染结果，强制同步 flush），却用已累加本次 delta 的新 pan 反推布局原点，夹取窗口随拖动方向偏移一个事件增量——朝边界快拖会冲过头约一个步长再弹回（橡皮筋感，60px 边界余量被吃掉）。
- **交互细节**：两项修复，行为零变化——① `.board-wrap.gesturing #board` **手势期整板提层**：平移 / 双指缩放 / 滚轮期间 `will-change: transform`，光栅一次后位移全部为纯合成器变换，随 `.gesturing` 移除即释放；不采用常驻提层（F-518 备注的分数缩放常驻 will-change 光栅 scale 失稳病理）；② **手势期几何常量缓存** `vpGeom`：手势开始（pointerdown / 滚轮突发起点）量测一次 wrap 矩形 + 棋盘未变换布局原点 / 布局尺寸，`clampPan` / `zoomAt` 全程用常量（transform 不参与布局，手势内恒定），消除每事件 2 次 rect 读与滞后一拍偏差；pointerup 清空指针 / 滚轮 180ms 定时器到点 / `fitBoard` 时失效。顺手：`transformOrigin='0 0'` 由 `applyViewport` 每帧重写改为构造时一次写入。
- **验收标准**：476 块缩放 0.5 空白拖拽平移位移 1:1 跟随（指针步进累加与棋盘位移逐点相等）；板大于场（缩放 1.66）时左右夹取精确命中 60px 边界（实测 1220/1220、-2011.8/-2011.8，无冲过头回弹）；0.5~6 缩放钳制正常；非夹取态滚轮缩放锚点漂移 = 0；手势期 `#board` 计算样式 will-change=transform、空闲=auto（提层仅存在于手势窗口）；平移 / 缩放后拼块拖拽量测重测正确；`tsc` 与全部测试通过。帧级流畅度按 F-518 方法论备注在真实浏览器 DevTools 验收。
